03Running a machine-coding round

Different discipline from an algorithm round. Here you are being watched build software, not solve a puzzle — so the sequencing of what you write matters as much as the code.

MinutesDo this
0–7Scope out loud, then get agreement. "I'll build X with these four operations. I'm going to skip Y and Z unless we have time — is that the right cut?" Machine-coding rounds are lost by attempting too much, not by attempting too little.
7–15Write the types and protocol boundaries first — no bodies. Enums for the data model, protocols where I/O crosses the boundary, the public API of the main service. Then say: "before I fill these in, does this shape look right to you?" This single checkpoint is the highest-value thing you do all round.
15–55Implement depth-first through one complete happy path so something runs early. A working narrow slice beats four half-built layers.
55–70Edge cases and errors. Say them aloud as you handle them. The reported grading criteria name edge cases explicitly — treat this as a scored section, not cleanup.
70–85Tests. Also explicitly named in the grading. Even six assertions. Write them yourself before being asked.
85–90State what you'd do next with more time, and ask how their real implementation differs.
The habit that wins these rounds: narrate design decisions as trade-offs, not as facts. "I'm making the store a protocol so tests can use an in-memory version — costs a little indirection, buys testability." Two panelists means one is often assessing exactly this.
Do not gold-plate. The most common senior failure in machine coding is building an elegant abstraction layer and running out of time before anything works. Working and plain beats beautiful and unfinished, every time.

04The optimization challenge

Reported in the 30-minute engineering screen and in an earlier round. Short, and there are only about five underlying answers.

The reported case: sequential calls that should be concurrent

// BEFORE — three independent calls, run one after another. 3× latency.
func loadDashboard() async throws -> Dashboard {
    let user   = try await fetchUser()
    let alerts = try await fetchAlerts()
    let policy = try await fetchPolicy()
    return Dashboard(user: user, alerts: alerts, policy: policy)
}

// AFTER — independent work overlaps. Latency = slowest call, not the sum.
func loadDashboard() async throws -> Dashboard {
    async let user   = fetchUser()
    async let alerts = fetchAlerts()
    async let policy = fetchPolicy()
    return Dashboard(user: try await user,
                     alerts: try await alerts,
                     policy: try await policy)
}

Then say the three things that turn a correct answer into a senior one:

  • Check the dependency graph first. Only genuinely independent calls parallelise. If fetchPolicy needs the user's org ID, it stays sequential — and saying that shows you read the code rather than pattern-matched.
  • Failure semantics change. With async let, one throw cancels the siblings. Is that what you want, or should a failed alerts fetch still render the dashboard? If partial results are acceptable, use a task group collecting Result.
  • Bound the fan-out. Three is fine; three hundred needs a task group with a concurrency limit, or you stampede the backend.

The other four shapes, and their tells

Tell in the codeFix
Nested loop comparing two collectionsO(n²) → hash set or dictionary → O(n). The most common optimization question in existence.
A query or call inside a loopN+1. Batch into one call, or preload into a map.
Invariant work computed inside a loopHoist it out. Or memoise if the input repeats.
String concatenation or array append in a hot loopReserve capacity; build once; avoid repeated reallocation.
Repeated linear scans of the same dataBuild the index once, query many times.
Always open with the same sentence: "Before changing anything — what does the profile say, and what's the input size?" It costs five seconds, it's what you'd actually do, and it stops you optimising the wrong loop. Then optimise anyway; they want to see the change.

05What "clean class structure" is actually graded on

The Bengaluru report names this explicitly. Here is what it means concretely, so you can hit it deliberately.

  • One reason to change per type. A parser parses. A store stores. A tokenizer that also handles file I/O will be called out.
  • Protocols at every I/O boundary. Filesystem, clock, network, object store. Not for architectural purity — so tests can inject fakes. Say that reason out loud; it converts an abstraction from overhead into justification.
  • Value types for data, classes for services. Records, tokens, commits, log lines are structs. Repositories, stores, pipelines are final classes.
  • Typed errors, not strings. An enum conforming to Error with the offset or context attached. In a parser, an error that says what and where is a feature.
  • Dependencies injected through the initialiser. No singletons, no global state, nothing reaching out to the filesystem from three layers deep.
  • No god object. If your Repository class has grown past ~8 methods, split it and say why.
  • Name things after the domain. ObjectStore, Commit, Index — not DataManager, Helper, Utils.

06Problem A · JSON parser

Highest-probability single problem. It is on the reported list, it is a perfect 90-minute machine-coding scope, and for a security company it doubles as an untrusted-input exercise — which maps directly onto the JD line about processing untrusted data.

Problem A"Write a JSON parser."

Step 1 — the data model, written first

indirect enum JSONValue: Equatable {
    case null
    case bool(Bool)
    case number(Double)
    case string(String)
    case array([JSONValue])
    case object([String: JSONValue])
}

struct JSONError: Error, Equatable {
    enum Kind: Equatable {
        case unexpectedEnd
        case unexpectedByte(UInt8)
        case invalidNumber
        case invalidEscape
        case invalidUTF8
        case depthLimitExceeded      // ← security, not correctness
        case inputTooLarge
        case duplicateKey(String)
        case trailingData
    }
    let kind: Kind
    let offset: Int              // byte offset — errors must locate themselves
}

Step 2 — the limits type. Introduce this unprompted.

struct JSONLimits {
    var maxDepth: Int = 128          // recursive descent + deep nesting = stack overflow
    var maxBytes: Int = 8 << 20      // 8 MB — bound the allocation up front
    var rejectDuplicateKeys = true  // {"a":1,"a":2} is a real parser-differential bug
    static let `default` = JSONLimits()
}
This is the single highest-scoring move in the problem. Say: "Since this parses untrusted input, I'll bound depth and size before writing any parsing code. A recursive-descent parser on deeply nested input is a stack-overflow DoS, and duplicate-key handling that differs between parsers is how filter-bypass bugs happen." For a manager who used to do penetration testing, that sentence lands harder than a fast implementation.

Step 3 — the parser core

struct JSONParser {
    private let bytes: [UInt8]      // UTF-8 bytes, not Characters — grapheme
    private var i = 0              // processing is wrong AND slow here
    private var depth = 0
    private let limits: JSONLimits

    static func parse(_ text: String,
                      limits: JSONLimits = .default) throws -> JSONValue {
        try parse(Array(text.utf8), limits: limits)
    }

    static func parse(_ bytes: [UInt8],
                      limits: JSONLimits = .default) throws -> JSONValue {
        guard bytes.count <= limits.maxBytes else {
            throw JSONError(kind: .inputTooLarge, offset: 0)
        }
        var p = JSONParser(bytes: bytes, limits: limits)
        let value = try p.parseValue()
        p.skipWhitespace()
        guard p.i == bytes.count else {          // "{} garbage" must fail
            throw JSONError(kind: .trailingData, offset: p.i)
        }
        return value
    }

    private mutating func parseValue() throws -> JSONValue {
        depth += 1
        defer { depth -= 1 }
        guard depth <= limits.maxDepth else {
            throw JSONError(kind: .depthLimitExceeded, offset: i)
        }

        skipWhitespace()
        guard i < bytes.count else { throw err(.unexpectedEnd) }

        switch bytes[i] {
        case UInt8(ascii: "{"):  return .object(try parseObject())
        case UInt8(ascii: "["):  return .array(try parseArray())
        case UInt8(ascii: "\""): return .string(try parseString())
        case UInt8(ascii: "t"):  try expect("true");  return .bool(true)
        case UInt8(ascii: "f"):  try expect("false"); return .bool(false)
        case UInt8(ascii: "n"):  try expect("null");  return .null
        default:                 return .number(try parseNumber())
        }
    }

    private mutating func parseObject() throws -> [String: JSONValue] {
        i += 1                                   // consume '{'
        var result: [String: JSONValue] = [:]
        skipWhitespace()
        if peek() == UInt8(ascii: "}") { i += 1; return result }

        while true {
            skipWhitespace()
            guard peek() == UInt8(ascii: "\"") else { throw err(.unexpectedByte(peek() ?? 0)) }
            let key = try parseString()

            if limits.rejectDuplicateKeys, result[key] != nil {
                throw JSONError(kind: .duplicateKey(key), offset: i)
            }

            skipWhitespace()
            try consume(UInt8(ascii: ":"))
            result[key] = try parseValue()

            skipWhitespace()
            switch peek() {
            case UInt8(ascii: ","): i += 1; continue     // note: trailing comma then
            case UInt8(ascii: "}"): i += 1; return result // hits the guard above → rejected
            case let b?:            throw err(.unexpectedByte(b))
            case nil:               throw err(.unexpectedEnd)
            }
        }
    }

    private mutating func skipWhitespace() {
        while i < bytes.count {
            switch bytes[i] {
            case 0x20, 0x09, 0x0A, 0x0D: i += 1   // space, tab, LF, CR — and NOTHING else.
            default: return                        // JSON whitespace is exactly these four.
            }
        }
    }

    @inline(__always) private func peek() -> UInt8? { i < bytes.count ? bytes[i] : nil }
    private func err(_ k: JSONError.Kind) -> JSONError { JSONError(kind: k, offset: i) }
}

Step 4 — the edge cases to name out loud

AreaWhat to handle and say
StringsEscapes \" \\ \/ \b \f \n \r \t and \uXXXX. Surrogate pairs — a \uD83D must be followed by a low surrogate or the string is invalid. Unescaped control bytes below 0x20 are illegal. Naming surrogate pairs unprompted is a strong marker.
NumbersLeading zeros are illegal (01). A leading + is illegal. .5 and 5. are illegal. NaN and Infinity are not JSON. Exponents are. Mention that Double loses precision on large integers and that a real parser keeps an integer case.
StructureTrailing commas rejected. Trailing data after the top-level value rejected. Empty input rejected. Bare top-level scalars are legal in modern JSON.
EncodingInput is UTF-8 bytes; invalid sequences must error rather than silently substitute. A BOM is not JSON whitespace.
SecurityDepth limit, size limit, duplicate keys, and no unbounded pre-allocation from a length field.

Extensions they'll ask for

  • "Make it faster." You're already on bytes rather than Characters — say so. Then: avoid String allocation for keys until needed, reserve capacity on containers, and consider a slice-based value type that defers materialisation.
  • "Stream it." Reshape into an event-emitting pull parser (.beginObject, .key, .value, .endObject) so a 2 GB document doesn't need 2 GB of memory. Very relevant to an endpoint agent parsing backend responses.
  • "Serialise too." Straightforward — but ask about key ordering. Deterministic output matters if anything downstream hashes or signs it.
  • "How would you test it?" See §10, and mention the JSONTestSuite corpus and fuzzing the parser.

07Problem B · Log parser, then scale it

Reported almost verbatim: build a log parser, then extend it to a distributed service. Two halves — machine coding, then HLD in the same session.

Problem B · part 1"Parse these logs and answer questions about them."
// The shape that scores: pluggable format, streaming, bounded memory.

struct LogRecord: Equatable {
    let timestamp: UInt64            // epoch nanos, normalised at parse time
    let level: Level
    let source: String
    let message: String
    let fields: [String: String]
}

enum Level: Int, Comparable {
    case debug, info, warn, error, fatal
    static func < (a: Level, b: Level) -> Bool { a.rawValue < b.rawValue }
}

// Protocol at the boundary → new formats without touching the pipeline.
protocol LineParser {
    func parse(_ line: Substring) -> Result<LogRecord, ParseFailure>
}

struct ParseFailure: Error { let line: String; let reason: String }

// Streaming source — never load the whole file.
protocol LineSource { mutating func next() -> Substring? }

final class LogPipeline {
    private let parser: LineParser
    private let filters: [(LogRecord) -> Bool]
    private var aggregators: [Aggregator]
    private(set) var malformedCount = 0     // count, don't crash, don't silently skip

    func run<S: LineSource>(_ source: inout S) {
        while let line = source.next() {
            guard !line.isEmpty else { continue }
            switch parser.parse(line) {
            case .failure:
                malformedCount += 1              // a real log file always has garbage lines
            case .success(let record):
                guard filters.allSatisfy({ $0(record) }) else { continue }
                for i in aggregators.indices { aggregators[i].consume(record) }
            }
        }
    }
}

protocol Aggregator { mutating func consume(_ r: LogRecord); func result() -> AggregateResult }
// e.g. CountByLevel, TopKSources, ErrorRatePerMinute (tumbling window)

The points that earn the marks

  • Streaming, not slurping. Say "logs are unbounded, so memory must be O(1) in file size" before you write anything.
  • Malformed lines are data, not exceptions. Count them and report. A parser that throws on line 4,000,000 of a production log is useless.
  • Format is injected. Syslog, JSON lines, and Apache combined all differ; the pipeline shouldn't care.
  • Timestamps normalised at the boundary. Time zones, missing years in syslog, and clock skew across hosts are all real. Mention out-of-order arrival — logs are not sorted.
  • Top-K needs a heap, not a full sort. If they ask for the top N sources, a bounded min-heap is O(n log k). Free complexity points.
Problem B · part 2"Now make it a distributed service."
  agents ──▶ LB ──▶ INGEST ──▶ partitioned log (Kafka) ──▶ STREAM WORKERS
   │                  │             partition by             │
   │                  │             tenant+source            ├─▶ hot store (time-series, 7d)
   │                  │                                      ├─▶ inverted index (search)
   │                  │                                      └─▶ cold store (object, 1y)
   │                  └─ auth, schema validation, rate limit per tenant
   └─ local spool + batch + compress + backoff (survive backend outage)

                                                    QUERY ──▶ hot ∪ cold, merged
They will askSay
PartitioningBy tenant + source so one tenant can't hot-spot a partition, and ordering is preserved within a source. Watch for a single huge tenant needing sub-partitioning.
Delivery guaranteeAt-least-once with idempotent writes keyed on a record hash. Exactly-once is expensive and rarely worth it for logs — pick, and justify.
BackpressureAgent-side spool with a disk cap and a drop policy. The agent must never block the host, and it must never grow unbounded.
Late and out-of-order dataWindowed aggregation with a watermark and a grace period; corrections after that go to a repair path.
Retention and costHot/warm/cold tiers, downsampled aggregates kept longer than raw. This is the answer that shows you've operated a system, not just drawn one.
CardinalityThe thing that actually kills log systems. Bound label cardinality at ingest or the index explodes.
Bring it home: "This is structurally the same problem as shipping endpoint telemetry off a million Macs — bounded local spool, batching, partitioned ingest, tiered retention." That reframes a generic exercise as their product, which is exactly the connection they're hoping a senior candidate makes.

08Problem C · Prototypal version control system

Reported as the LLD round. Pure object design — there is almost no algorithmic content, and it is graded on structure, tests and edge cases.

Problem C"Build a basic version control system."

Get the object model right and the rest follows

// Content-addressed storage: the ID *is* the hash of the content.
// This gives deduplication and integrity verification for free — say that.
struct ObjectID: Hashable, CustomStringConvertible {
    let hex: String
    var description: String { String(hex.prefix(8)) }
}

enum GitObject {
    case blob(Data)
    case tree([TreeEntry])
    case commit(Commit)
}

struct TreeEntry: Comparable {
    let name: String
    let id: ObjectID
    let kind: Kind            enum Kind { case blob, tree }
    // Sorted by name when serialised → identical content yields an identical
    // hash. Determinism is a requirement, not a nicety.
    static func < (a: Self, b: Self) -> Bool { a.name < b.name }
}

struct Commit {
    let tree: ObjectID
    let parents: [ObjectID]   // 0 = initial, 1 = normal, 2+ = merge
    let author: String
    let timestamp: Date
    let message: String
}

Boundaries as protocols — the part being graded

protocol ObjectStore {
    func put(_ object: GitObject) throws -> ObjectID
    func get(_ id: ObjectID) throws -> GitObject
    func contains(_ id: ObjectID) -> Bool
}

protocol RefStore {
    func resolve(_ name: String) throws -> ObjectID?
    func update(_ name: String, to id: ObjectID) throws
    func listBranches() -> [String]
    var head: Head { get set }        enum Head { case branch(String), detached(ObjectID) }
}

protocol FileSystem {                    // ← injectable: tests use an in-memory impl
    func read(_ path: String) throws -> Data
    func write(_ data: Data, to path: String) throws
    func listFiles(under path: String) throws -> [String]
    func delete(_ path: String) throws
}

final class Index {                       // the staging area
    private var staged: [String: ObjectID] = [:]
    func stage(path: String, id: ObjectID) { staged[path] = id }
    func unstage(path: String)             { staged[path] = nil }
    func buildTree(in store: ObjectStore) throws -> ObjectID { /* nested dirs → nested trees */ }
}

final class Repository {
    private let objects: ObjectStore
    private let refs: RefStore
    private let fs: FileSystem
    private let index: Index

    init(objects: ObjectStore, refs: RefStore, fs: FileSystem, index: Index = Index()) { … }

    func add(_ path: String) throws
    func commit(message: String, author: String) throws -> ObjectID
    func log(from: ObjectID?) throws -> [Commit]
    func branch(_ name: String) throws
    func checkout(_ target: String) throws
    func diff(_ a: ObjectID, _ b: ObjectID) throws -> [Change]
    func merge(_ branch: String) throws -> MergeResult
}

Say these while designing

  • Content addressing buys dedup and integrity. Two identical files stored once; a corrupted object is detectable because its content no longer hashes to its name.
  • Determinism. Sorted tree entries and a canonical serialisation, so the same tree always produces the same hash. Without it nothing else works.
  • Three protocols, one concrete class. The Repository orchestrates; storage, refs and the filesystem are injected. Tests construct a repository entirely in memory with no temp directories.
  • Scope honestly. "I'll implement init, add, commit, log and branch fully. Merge I'll do fast-forward only, and I'll describe three-way merge rather than build it." Naming the cut is a senior behaviour; silently running out of time is not.

Edge cases — call these before they do

CaseBehaviour
Commit with nothing stagedReject with a clear error, or allow with a flag. Decide and say which.
Initial commitZero parents. The special case that breaks naive log traversal.
Detached HEADModel HEAD as an enum of branch-or-commit. Modelling it as a string is the bug.
File deleted from the working treeTree diff must produce a deletion, not silently keep the old blob.
Nested directoriesTrees contain trees. Recursion, and a depth guard.
Branch name collides with an existing refReject.
Checkout with uncommitted changesRefuse, or stash. State the policy.
Merge baseLowest common ancestor of two commits. Say "I'd BFS both parent chains and find the first common node" even if you don't implement it.
Empty file vs missing fileDifferent objects. Easy to conflate.
Line worth having ready: "This is content-addressed storage with a DAG on top — the same shape as the provenance graph in a lineage product, where nodes are immutable and identity comes from content." It connects the exercise to their domain without being forced.

09Problem D · Logging service

Reported as a named problem. Can arrive as machine coding (build the client library) or as design (build the service). Prepare the library; the service is Problem B part 2.

Problem D"Build a logging service like Datadog."

If it's machine coding, they mean the client library

protocol LogSink { func write(_ batch: [LogRecord]) }

final class Logger {
    private let minLevel: Level
    private let sinks: [LogSink]
    private let buffer: BoundedQueue<LogRecord>   // see v1 doc §07
    private let sampler: Sampler
    private let clock: Clock                      // injected → testable

    func log(_ level: Level, _ message: @autoclosure () -> String,
             fields: [String: String] = [:]) {
        // 1. Level check FIRST, and @autoclosure means the message string is
        //    never built when the log is filtered out. Free win; mention it.
        guard level >= minLevel else { return }
        // 2. Sample high-volume low-value levels.
        guard sampler.shouldEmit(level) else { return }
        // 3. Never block the caller. Bounded buffer, drop with a counter.
        buffer.enqueue(LogRecord(timestamp: clock.nowNanos(), level: level,
                                 source: currentSource(), message: message(),
                                 fields: fields))
    }
    // A background drain batches from the buffer into the sinks.
}
  • @autoclosure on the message so string interpolation is never evaluated for a filtered-out log. Small, specific, and exactly the kind of thing that reads as experience.
  • Logging must never block or crash the host application. Bounded buffer, drop and count, async drain. Same principle as the sensor.
  • Structured fields, not formatted strings — you can't query a sentence.
  • Injected clock for deterministic tests.
  • Sampling and rate limiting as first-class features, not afterthoughts.

10Tests and edge cases

Explicitly named in the reported grading criteria, which makes this a scored section rather than a nicety. Budget real time for it.

The test ladder — write these in order

TierWrite
1 · Happy pathOne test that proves the thing works end to end. Do this the moment the happy path compiles.
2 · BoundariesEmpty input, single element, at-capacity, one-past-capacity. This tier catches most real bugs.
3 · Malformed inputFor a parser this is the main event: truncated, garbage bytes, wrong types, deeply nested. Assert the specific error and offset, not just that it threw.
4 · Round-trip / invariantsparse(serialise(x)) == x. For a queue: enqueued == drained + dropped. Invariant tests find bugs example tests miss.
5 · AdversarialDepth bombs, huge inputs, duplicate keys, pathological cases. For a security company, describing how you'd fuzz it is worth as much as writing another test.
Say this once during the round: "For a parser handling untrusted input I'd add a fuzzing target in CI alongside the unit tests — most parser bugs that matter are found by a fuzzer, not by a test author." True, cheap, and precisely aimed at this company.

Make everything testable by injecting three things

protocol Clock: Sendable { func nowNanos() -> UInt64 }
protocol FileSystem { /* read / write / list / delete */ }
protocol IDGenerator { func next() -> String }

// Real implementations in production, fakes in tests. No temp directories,
// no sleeps, no wall-clock dependence, no flaky tests.
final class FakeClock: Clock {
    private var t: UInt64 = 0
    func nowNanos() -> UInt64 { t }
    func advance(seconds: Double) { t &+= UInt64(seconds * 1e9) }
}

Introducing the Clock protocol in the first ten minutes — before any test exists — is one of the clearest senior signals available in a machine-coding round. It says you write code you intend to test.

11Concurrency — now secondary, still worth having

Demoted, not deleted. It remains the answer to optimization questions, it's plausible as an extension on an endpoint team, and version 1 of this document has the full treatment with working implementations.

Keep these ready

  • The parallelise-independent-work answer from §04. Highest-probability use of concurrency in this loop.
  • The UnfairLock wrapper and why var lock = os_unfair_lock() as a property is undefined behaviour. One minute of value if a thread-safety extension appears.
  • "Now make it thread-safe" as an extension on any component you build: lock the mutable state, keep critical sections O(1), never call an injected closure while holding the lock.
  • The GCD-vs-actors opinion. Structured concurrency above the ingest boundary; no actor in a deadline-bound callback path, because an actor hop is a suspension with unbounded queuing latency.
  • Bounded queue with drop accounting — reusable in the logging-service problem and in any "the consumer is slower than the producer" follow-up.
  • Thread Sanitizer in CI as the answer to "how do you find data races."

12Swift rapid-fire bank

Trimmed to what survives a machine-coding round. Skim the morning of.

QuestionAnswer
struct vs class?Value semantics and no identity vs identity, shared mutable state, deinit, inheritance. Data is structs; services are final classes.
Why indirect enum?Recursive enum cases need heap indirection — a JSONValue containing [JSONValue] is the canonical example.
How does CoW work?Shared buffer until mutation; isKnownUniquelyReferenced triggers the copy.
weak vs unowned?weak is optional and zeroes, costs a side-table lookup; unowned is non-optional and faster but traps after dealloc.
Is lazy var thread-safe?No. Global and static let are.
some vs any?Opaque single concrete type resolved at compile time vs boxed existential with dynamic dispatch.
throws vs Result?throws for synchronous flow; Result when you need to store, pass, or collect outcomes — e.g. per-line parse failures.
What is @autoclosure for?Defer evaluation of an argument — avoids building a log message that gets filtered out.
Why parse bytes, not Characters?Swift Character is a grapheme cluster: correct for text, wrong and slow for byte-oriented formats.
size vs stride?Bytes used vs bytes per array element with padding. Allocate with stride.
Lifetime of a withUnsafeBytes pointer?Valid only inside the closure. Escaping it is undefined behaviour.
DispatchQueue.sync deadlock?Calling sync on the queue you're already running on.
Semaphore in async code?Don't — blocking a cooperative-pool thread can deadlock the runtime.
How do you find a data race?Thread Sanitizer plus invariant stress tests. Not by reading.
defer ordering?Reverse declaration order, on every exit path including throws.
