01Day 1 · Swift sweep

You've written Swift for years. This day is not learning — it's finding the four or five things you'd fumble if asked to justify them out loud, and refreshing the standard library surface you'll type under pressure.

Day 1Language + standard library2.5 hrs
Read — 45 min

Work through the API reference in this document, section by section. Don't memorise; mark anything you couldn't have typed from memory. Those marks are your real study list.

Build — 60 min · warm-up katas

Small, fast, all in the test target. The point is fluency with the standard library, not difficulty.

// 1. Word frequency, top K by count then alphabetically.
func topWords(_ text: String, k: Int) -> [(String, Int)]

// 2. Group log lines by level. Practise Dictionary(grouping:by:).
func groupByLevel(_ lines: [String]) -> [String: [String]]

// 3. Merge overlapping intervals. Classic, and it appears everywhere.
func merge(_ intervals: [(Int, Int)]) -> [(Int, Int)]

// 4. Parse "key=value; key2=value2" into a dictionary, tolerating junk.
func parseFields(_ s: Substring) -> [String: String]

// 5. Custom Sequence: iterate lines from a big string WITHOUT splitting
//    the whole thing into an array. Direct rehearsal for the log parser.
struct LineIterator: Sequence, IteratorProtocol { … }

Number 5 matters most — it forces you through Sequence/IteratorProtocol and Substring, both of which show up in the log-parser problem.

Drill — 30 min
  • Write an enum with associated values plus a recursive indirect case, and pattern-match it exhaustively. This is the JSON value model.
  • Write a typed error enum with context, and both throws and Result versions of the same function. Know when you'd pick each.
  • Write a protocol with an associatedtype, and a generic function constrained to it.
Say out loud — 15 min
"Structs for data, final classes for services. Protocols at the I/O boundary so tests can inject fakes — that's the reason, not architectural purity."

02Day 2 · JSON parser

The highest-probability single problem, and the best training exercise regardless — it exercises data modelling, error design, edge cases, untrusted input and testing in one build.

Day 2Build the parser, slowly3 hrs
Build — 2 hrs · no time pressure, understand every decision

Work from the revised prep document's Problem A, but type it, don't copy it. Order matters — build in the order you'd build it in the interview:

StepWhat
1JSONValue indirect enum + JSONError with kind and byte offset.
2JSONLimits — depth, size, duplicate-key policy. Before any parsing code.
3Scaffold: byte array, cursor, peek(), skipWhitespace(), err().
4parseValue() dispatch on first byte, with the depth guard.
5Literals (true/false/null) — easiest, gets something running.
6Strings with full escapes including \uXXXX and surrogate pairs.
7Numbers with the illegal forms rejected.
8Arrays, then objects. Trailing-comma and trailing-data rejection.
Do not skip surrogate pairs. It's the one part everyone hand-waves, it's genuinely fiddly, and getting it right in practice means you can mention it confidently in the room even if you don't implement it there.
Test — 45 min

Write the five tiers from the revised doc's §10. Minimum bar before you stop:

func testNestedObject()          // happy path
func testEmptyObjectAndArray()   // boundaries
func testTruncatedInput()        // assert the SPECIFIC error + offset
func testTrailingComma()
func testLeadingZeroRejected()
func testDepthBombRejected()     // String(repeating: "[", count: 10_000)
func testDuplicateKeyRejected()
func testSurrogatePair()         // "\uD83D\uDE00" == "😀"
func testInvalidUTF8()
func testRoundTrip()             // if you also wrote a serialiser

Assert error kind and offset, not just that something threw. Precise error tests are themselves a signal.

Say out loud — 15 min
"Since this parses untrusted input, I'll bound depth and size before writing any parsing code. Recursive descent on deeply nested input is a stack-overflow DoS, and duplicate-key handling that differs between parsers is how filter-bypass bugs happen."

Say it until it's one fluid sentence. For a manager with a penetration-testing background, this is the highest-value thirty seconds in the round.

03Day 3 · LLD and architecture

The reported LLD round asks for a prototypal version control system, graded on class structure, tests and edge cases. This day is about designing boundaries fast and defending them.

Day 3Version control system3 hrs
Design on paper — 40 min

Before any code: draw the object model and the protocol boundaries from memory. Target ten minutes to produce ObjectID, GitObject, TreeEntry, Commit, plus ObjectStore, RefStore, FileSystem and the Repository API. Do it three times until it flows.

Build — 100 min

Implement a working subset, in memory only:

  • InMemoryObjectStore with SHA-256 content addressing (import CryptoKit, SHA256.hash(data:)).
  • InMemoryFileSystem — a dictionary of path to Data. This is your test double.
  • Index with stage and buildTree, handling nested directories.
  • Repository.add, .commit, .log. Stop there.
The point of this day isn't a working VCS. It's building the reflex of starting from protocol boundaries with injected dependencies, so that in the room your first ten minutes produce a shape a panelist can approve.
Drill — 25 min

Write out the edge-case table from memory — empty commit, initial commit with zero parents, detached HEAD as an enum, file deletion, nested directories, checkout with uncommitted changes, merge base via lowest common ancestor. Getting these out loud before being asked is a large part of the grade.

Say out loud — 15 min
"Content addressing gives me deduplication and integrity for free — identical content stored once, and corruption is detectable because the object no longer hashes to its name. Tree entries are sorted so serialisation is deterministic."

04Day 4 · Log parser and scale-out

Double-counted effort: this is a likely coding problem and half of your system-design round.

Day 4Streaming pipeline3 hrs
Build — 100 min
  • LogRecord, Level: Comparable, LineParser protocol, two conforming parsers (syslog-ish and JSON-lines — the second reuses day 2's work).
  • Streaming LineSource using your day-1 iterator. Never load the file whole; say why.
  • LogPipeline with filters, a malformed-line counter, and pluggable aggregators.
  • Two aggregators: CountByLevel, and TopKSources using a bounded min-heap — O(n log k), not a full sort.
  • A tumbling-window aggregator (errors per minute) so you've handled time bucketing once.
Drill — 40 min · the scale-out

Draw the distributed diagram from the revised doc four times, from memory, out loud, in under five minutes each: agents → spool → ingest → partitioned log → stream workers → hot index + cold store → query. Each pass, force yourself to name partitioning key, delivery guarantee, backpressure, late data, retention tiers, and cardinality.

Say out loud — 20 min
"Structurally this is the same problem as shipping endpoint telemetry off a million Macs — bounded local spool, batching with backoff, partitioned ingest, tiered retention. The agent must never block the host and never grow unbounded."

05Day 5 · Concurrency and optimization

Secondary for the main round but the answer to the optimization challenge, and the most likely extension question on an endpoint team.

Day 5Concurrency + perf drills2.5 hrs
Build — 70 min
  • UnfairLock wrapper from memory. Then explain out loud why var lock = os_unfair_lock() as a stored property is undefined behaviour.
  • BoundedQueue — ring buffer, drop policy, drop counter, bulk drain. From memory, twice.
  • Take day 4's LogPipeline and make it thread-safe: multiple producer threads, one drain. Then write the invariant test: enqueued == drained + dropped.
  • Run that test under Thread Sanitizer: swift test -Xswiftc -sanitize=thread. Watch it catch something.
Drill — 45 min · optimization reps

Write the slow version, then fix it, six times. Speed matters more than novelty here:

1. Three sequential awaits          → async let / task group
2. Nested loop over two arrays      → Set or Dictionary lookup
3. Call inside a loop (N+1)         → batch or preload into a map
4. Invariant work inside a loop     → hoist out
5. String += in a loop              → reserveCapacity, build once
6. Repeated linear scan             → build an index once

For number 1, rehearse the three caveats: check the dependency graph, decide the failure semantics, bound the fan-out.

Say out loud — 15 min
"Structured concurrency above the ingest boundary — the cancellation and isolation guarantees are worth a lot in a long-lived daemon. But no actor in a deadline-bound callback path: an actor hop is a suspension with unbounded queuing latency, and that path answers to the kernel."

06Day 6 · Timed mocks

The highest-value day by a wide margin. Everything before this was input; this is the first time you produce under the actual constraint.

Day 6Two full-length mocks5 hrs
Mock 1 — 90 min, cold, timed

Prompt: "Write a JSON parser." Blank file. Timer visible. Talk out loud the whole time — record yourself on your phone if nobody's available to sit in.

Hit the checkpoints from the revised doc: scope by minute 7, types and protocols by 15, running happy path by 55, edge cases by 70, tests by 85.

Review — 45 min

Play the recording back. Score yourself honestly on five things:

CheckPass looks like

Did you write types before bodies?A reviewable shape existed by minute 15.
Did you narrate trade-offs?At least four "I'm doing X rather than Y because Z."

07Day 7 · Repair and rehearse

Light day. Fix what the mocks exposed, warm the verbal material, stop early.

Day 7Targeted repair3 hrs
Repair — 90 min

Only the three weaknesses from day 6. If string escapes cost you twenty minutes, rewrite just parseString three times. If you never got to tests, practise writing the test file first. Do not start anything new today.

Rapid-fire — 30 min

Cover the answers in the revised doc's §12 and speak each one. Anything you stumble on, write out once by hand.

Rehearse — 30 min

The four set pieces, spoken, twice each: the untrusted-input limits line, content addressing, the concurrency opinion, the telemetry-pipeline parallel. These are the sentences that make you sound like the team's colleague rather than a candidate.

Prepare the room — 30 min
  • Xcode open, package building, tests green, before the call starts.
  • Screen-share tested. Font size up — panelists reading 11pt over a video call is a real friction you can remove.
  • Notifications off, Do Not Disturb on, second monitor cleared.
  • Water, paper, pen. Some problems are faster drawn than typed.
Stop by early evening. Ninety minutes of live problem-solving with two engineers is an endurance task. Being rested outperforms one more hour of drilling, and this is one of the few pieces of interview advice that is unambiguously true.

08The Swift API reference

What you'll actually reach for in these problems. Read it once on day 1, mark the gaps, skim it the morning of.

Strings — where most parser bugs live

text.split(separator: "\n", omittingEmptySubsequences: false)  // → [Substring]
text.utf8            // UTF8View — bytes. Use this for parsing.
text.unicodeScalars  // code points
text.count           // GRAPHEME clusters — O(n), not byte length!
Array(text.utf8)     // materialise bytes once, index with Int

String(decoding: bytes, as: UTF8.self)   // length-bounded, safe
String(cString: ptr)                     // requires NUL termination — DANGEROUS on tokens
UInt8(ascii: "{")                        // byte literal, compile-time

text.hasPrefix / .hasSuffix / .lowercased()
text.trimmingCharacters(in: .whitespacesAndNewlines)   // Foundation
text.components(separatedBy: ",")                      // Foundation → [String]
text.replacingOccurrences(of:with:)                    // Foundation

// Index arithmetic — String indices are opaque, not Int.
let i = text.index(text.startIndex, offsetBy: 5)
text[i...]  text[..<i]  text.distance(from:to:)
The Substring trap. A Substring keeps its parent String's entire storage alive. Slicing one line out of a 500 MB log and storing it retains all 500 MB. Convert to String when you keep it; stay on Substring when you're just passing through. This is a genuine memory bug and a great thing to mention unprompted.

Concurrency

// GCD
let q = DispatchQueue(label: "x")                       // serial by default
DispatchQueue(label: "y", attributes: .concurrent)
q.async { }   q.sync { }   q.async(flags: .barrier) { }  // barrier = writer
q.asyncAfter(deadline: .now() + .milliseconds(50)) { }
DispatchGroup · DispatchSemaphore · DispatchSource.makeTimerSource

// Structured concurrency
async let a = f();  async let b = g();  let (x, y) = try await (a, b)

try await withThrowingTaskGroup(of: T.self) { g in
    for item in items { g.addTask { try await work(item) } }
    for try await r in g { collect(r) }
}
Task { }  ·  Task.detached { }  ·  Task.isCancelled  ·  try await Task.sleep(for: .seconds(1))

actor Cache { var items: [K: V] = [:] }    // isolated; reentrant at every await
@MainActor  ·  nonisolated  ·  Sendable  ·  @unchecked Sendable

// AsyncStream — bridge a callback API into async, WITH backpressure
let (s, c) = AsyncStream<E>.makeStream(bufferingPolicy: .bufferingNewest(1024))
c.yield(e)   // returns .enqueued / .dropped / .terminated — check it

// Bridge a completion handler to async
try await withCheckedThrowingContinuation { cont in
    legacyAPI { result, error in
        if let error { cont.resume(throwing: error) } else { cont.resume(returning: result!) }
    }   // resume EXACTLY once — twice traps, zero leaks the task forever
}

09Traps that cost interviews

TrapWhat actually happens
text.count for byte lengthCounts grapheme clusters in O(n). Wrong answer and slow. Use text.utf8.count.
Storing a SubstringRetains the whole parent string's storage.
Data slice indicesdata[5...] still starts at index 5, not 0. Off-by-everything bugs.
String(cString:) on a length-delimited bufferOver-reads past the end. In a security product this is the bug.
var lock = os_unfair_lock() as a propertyUndefined behaviour — exclusivity may hand you a copy. Threads lock different memory and it appears to work.
lazy var from two threadsNot thread-safe. Global and static let are.
Concurrent queue + async mutationMultiple writers into a Dictionary. Non-deterministic crashes.
DispatchSemaphore inside async codeBlocks a cooperative-pool thread; can deadlock the runtime.
Calling an injected closure while holding a lockReentrancy deadlock. Swap state out under the lock, call out after.
Date() for elapsed timeWall clock jumps on NTP and sleep/wake. Use CLOCK_MONOTONIC_RAW.
Creating a DateFormatter per lineExtremely expensive. Create once, reuse.
Escaping a withUnsafeBytes pointerCompiles, then corrupts. Valid only inside the closure.
Dictionary(uniqueKeysWithValues:) on real dataTraps on duplicate keys. Use init(_:uniquingKeysWith:).
Resuming a continuation twiceTraps. Never resuming leaks the task forever.
