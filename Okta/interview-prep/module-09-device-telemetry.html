Device Telemetry & Unified Device Trust Layer (BAN-3495)

From fragmented posture silos to event-driven deltas - the architectural problem both JumpCloud and Okta must solve for true Zero Trust.

← Module 08 Hub Module 10 →

Concept Summary

Zero Trust fails when posture data is stale. JumpCloud today has 3–4 silos (SI osquery snapshots, Mongo system report, ephemeral DURT signals, MDM Postgres) with 5 min–2 hr latency. BAN-3495 proposes near-real-time attribute deltas via PushEvents into UDTL (ZR-2375 platform), consumed by CAP and BeyondCorp (BAN-3496).

Design Principles

Deltas, not snapshotsOne JSON message per attribute change - not 60 SI table rows
Canonical namespacedisk_encryption.status, os.version - one key across sources

Bootstrap + deltachange_type: created on enroll, then updated
Delivery modesEvent (<30s), On-change (<60s), Bootstrap

Okta Parallel

Okta auth policies evaluate device risk signals at authentication time - device trust must be continuously updated as posture changes. Okta's device object in Universal Directory with risk signals parallels UDTL's device_attribute_state + compliance_verdicts. The interview insight: both vendors move from point-in-time login checks to continuous evaluation architectures.

Interview Q&A

Why not just poll osquery more frequently?
Polling is still snapshot-based - you discover changes only at poll interval, burn CPU/battery, and SI path is fire-and-forget HTTP 200 with no ack. Zero Trust needs push deltas with explicit delivery confirmation and sub-minute SLA for critical attrs like FDE status.
MDM > Agent precedence - example?
FileVault reported in both Apple MDM SecurityInfo and agent osquery. MDM is authoritative for enrollment state and Apple-native security attrs; agent enriches firewall and EDR where MDM lacks visibility. Precedence engine resolves conflicts to single device_attribute_state.
Producer vs consumer split?
Bandipur (BAN-3495) owns producers only - agent + MDM forwarders. Zirconium (ZR-2375) owns UDTL platform. CAP and BeyondCorp are parallel consumers of same 19 attributes - avoids N duplicate telemetry pipelines. Strong system design answer for staff-level interviews.
What's shipped vs in flight?
Shipped: signal collectors for Go, CAP PDP, MDM ES profile provisioning. In flight: telemetry/ pipeline, PushEvents contract, UDTL platform, BeyondCorp consumer. Frame as: "I've worked producer-side contracts and cross-team RFCs; platform storage is Zirconium scope."

Gaps & Honest Limits

  • UDTL platform is ZR-2375 - BAN-3495 uses MockPublisher until ingestion API in staging.
  • BAN-3496 BeyondCorp consumer blocked on ZR consumption API (~Oct 2026 optimistic).
  • v1 scope: macOS + Windows only - no Linux producers.
