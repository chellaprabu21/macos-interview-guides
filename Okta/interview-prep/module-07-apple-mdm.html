Apple MDM as Security Control Transport

MDM is the provisioning plane - SCEP enrollment, profile delivery, ES entitlements - that enables the agent runtime plane.

Concept Summary

Apple MDM is how enterprises bootstrap trust on macOS: enroll device, install identity certs, deploy configuration profiles (SSO extension, login items, system extension policies), and push security commands. JumpCloud operates a full MDM stack in jumpcloud-apple-mdm - check-in protocol, SCEP, APNs push, DDM - that provisions capabilities the agent consumes at runtime.

JumpCloud Implementation

  • jumpcloud-apple-mdm/endpoints/checkin.go - Authenticate, TokenUpdate, CheckOut; Mdm-Signature PKCS#7 verify
  • jumpcloud-apple-mdm/business/checkin.go - enrollment command chain, APNs push, bootstrap token
  • jumpcloud-apple-mdm/business/templates.go - ES system extension profile (com.apple.system-extension-policy)
  • jumpcloud-apple-mdm/commands/results/handlers/endpoint_security_profile_handler.go - auto-enqueue ES profile if missing
  • jumpcloud-apple-mdm/services/scep.go - CSR signing, challenge password
  • jumpcloud-apple-mdm/business/checkin_ddm_declaration.go - Declarative MDM
  • jumpcloud-agent/mdm/ - agent-side MDM association reporters

Check-in verifies Mdm-Signature header (PKCS#7 over body with device identity cert) before dispatching message type. During enrollment, business logic chains commands: install profiles → ES entitlement → agent association.

Okta Parallel

Okta Device Access deploys via MDM: Platform SSO extension profiles, Device Access SCEP certificates, Okta Verify login items, and com.apple.extensibility.sso payloads. Same pattern - MDM is not the security product; it's the delivery mechanism for entitlements and configs that Okta Verify / Device Access consume at runtime.

Interview Q&A

Provisioning plane vs runtime plane?
MDM delivers entitlements and configs once (or on change). Agent/extensions enforce security continuously at runtime. ES entitlement without ES client binary is useless; ES client without MDM entitlement won't load. Both planes required.
How is ES entitlement delivered?
EndpointSecurityBuilder in templates.go builds com.apple.system-extension-policy payload allowing JumpCloud team ID + ES extension bundle ID. Handler auto-enqueues on ProfileList if com.jumpcloud.endpoint.security missing - self-healing enrollment.
What is DDM?
Declarative MDM - device pulls declarations and reports status vs classic push-command model. JumpCloud has DDM handlers for SecurityInfo and related declarations - relevant for BAN-3495 MDM producer path (FileVault status from MDM with MDM > Agent precedence).
Okta MDM deployment comparison?
Okta publishes .mobileconfig templates for SSO extension, login items, Device Access certs via customer's MDM (Jamf, Intune, etc.). JumpCloud IS the MDM - same payloads, integrated stack. Interview angle: you've seen both integrated and BYO-MDM deployment models.

Gaps & Honest Limits

  • Agent MDM hooks (jumpcloud-agent/mdm/) report association - deep MDM business logic is apple-mdm repo, not agent.
  • Microsoft MDM parity in jumpcloud-microsoft-mdm - lower priority for macOS-focused JD.
