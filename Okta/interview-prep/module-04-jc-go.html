JumpCloud Go (DURT) - Device-Bound App Access

Phishing-resistant, device-bound application access with live posture signals - JumpCloud's closest parallel to Okta FastPass + Device-Bound SSO.

Concept Summary

JumpCloud Go lets users open SSO-protected apps with minimal friction while proving they are on a managed device with acceptable posture. The client holds a DUK (Secure Enclave key), exchanges a DURT (refresh token) for a DUST (session token) on each access, and auth embeds a device assertion with live agent signals (~30s cache).

TermMeaning
DUKDevice User Key - TPM/Secure Enclave P256 signing key
DURTDevice User Refresh Token - exchanged on each app access
DUSTDevice User Session Token - consumed by auth/backend, not client

Okta Parallel

Okta FastPass provides silent, phishing-resistant app authentication when Okta Verify is running. Device-Bound SSO (dbSSO) cryptographically binds the browser session to the device via Secure Enclave + Device Access certs. JumpCloud Go combines both ideas: hardware-bound token refresh (DUK) + live posture evaluation at each app open - matching OIE policies that check device state per resource access.

Interview Sound Bite

"Unlike stale Mongo device claims at portal login (~2 hours old), JumpCloud Go evaluates live agent signals at each app open - same Zero Trust principle as Okta auth policies evaluating device state per resource, not just at initial SSO."

Interview Q&A

How is JumpCloud Go like Okta FastPass?
Both provide silent, possession-factor app access without password re-entry. Go uses DUK-signed DURT refresh; FastPass uses Okta Verify's device key + WebAuthn. Both require managed device enrollment and support CAP/OIE-style policy gates.
Why live signals at access time?
Posture can degrade between login and app access (FileVault disabled, EDR stopped). Point-in-time portal JWT is insufficient for Zero Trust. Agent collects OS, firewall, CrowdStrike ZTA, SentinelOne via signal/collector_darwin.go with ~30s cache to balance freshness vs performance.
Safari vs Chrome path?
Chrome/Firefox use browser extension + Native Messaging Host. Safari uses Apple's SSO Extension Policy + tray app (jcagent-tray-ssoe) - no browser extension. Same DURT backend, different IPC surface - important for macOS platform interview depth.
What happens if DUK is wiped?
User must re-register - same as Okta requiring FastPass re-enrollment after device cert deletion. Hardware binding is intentional: stolen session cookies without device key are useless.

Gaps & Honest Limits

  • DURT signals are ephemeral (not persisted) - BAN-3495/UDTL targets centralized posture store.
  • Go path not yet preferred over cert path in portal (ADR-011).
