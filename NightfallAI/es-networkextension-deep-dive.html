Part I

The Endpoint Security framework

ES is the only supported way to see and stop syscall-level activity on modern macOS. Everything a DLP agent knows about files and processes comes from here.

§1

Mental model — where ES actually sits

Get this right and the API stops being a list of function names.

  user process                 kernel                    your extension
  ────────────                 ──────                    ──────────────
  open("/x/secret.csv")
        │
        ├──── syscall ────────► vnode layer
        │                          │
        │                       MAC framework hook
        │                          │
        │                       ES kext (Apple's, in-kernel)
        │                          │
        │                          ├── builds es_message_t
        │                          ├── sends to EVERY subscribed client ──►  your callback runs
        │                          │                                          (userspace, root)
        │                       THREAD IS BLOCKED HERE                        │
        │                       waiting for every client's                    │
        │                       es_respond_auth_result()  ◄──────────────────┘
        │                          │
        │                       AND of all verdicts (any DENY wins)
        │                          │
        ◄──── returns fd ──────────┘   (or EPERM)

Four consequences fall straight out of that diagram, and they are the whole framework:

  1. You are in the syscall path. A human is waiting on your code. Not "your service has a latency SLO" — the open() is literally blocked in the kernel until you answer. This is why every design decision in an ES client is about latency.
  2. You are not alone. CrowdStrike, Jamf, the customer's other agent — all get the same message and all must respond. Your p50 doesn't set user experience; the slowest client's p99 does. And any single DENY wins, so you can never assume your ALLOW means the operation happened.
  3. The kernel does not trust you to be fast. Hence deadline. Miss it and the kernel kills your client so the system can make forward progress. This is the single most important fact in Part I.
  4. ES is a notification bus, not a data source. It tells you an open happened. It does not tell you what's in the file. Content is your problem, and reading the file is a separate, TCC-gated, re-entrant, deadlock-prone act.

§3

Your first client

Twenty lines that do the whole thing. Everything after this is discipline.

import EndpointSecurity
import Foundation

final class Sensor {
    private var client: OpaquePointer?
    // A DEDICATED serial queue. Never the main queue. Never a shared queue.
    private let esQueue = DispatchQueue(label: "ai.nf.es", qos: .userInteractive)

    func start() throws {
        var c: OpaquePointer?
        let res = es_new_client(&c) { [weak self] client, msg in
            // msg is ONLY valid inside this block unless you retain it.
            self?.handle(client: client, msg: msg)
        }

        guard res == ES_NEW_CLIENT_RESULT_SUCCESS, let c else {
            switch res {
            case ES_NEW_CLIENT_RESULT_ERR_NOT_ENTITLED:  throw Err.entitlement
            case ES_NEW_CLIENT_RESULT_ERR_NOT_PERMITTED: throw Err.fullDiskAccess
            case ES_NEW_CLIENT_RESULT_ERR_NOT_PRIVILEGED:throw Err.notRoot
            case ES_NEW_CLIENT_RESULT_ERR_TOO_MANY_CLIENTS: throw Err.tooManyClients
            default: throw Err.internalError
            }
        }
        client = c

        // 1. Mute yourself FIRST. Before subscribing. Always.
        var me = audit_token_t()
        // (obtain own audit token — see §10)
        es_mute_process(c, &me)

        // 2. Subscribe
        var events: [es_event_type_t] = [
            ES_EVENT_TYPE_AUTH_OPEN,
            ES_EVENT_TYPE_AUTH_EXEC,
            ES_EVENT_TYPE_NOTIFY_CLOSE,
            ES_EVENT_TYPE_AUTH_RENAME,
            ES_EVENT_TYPE_AUTH_COPYFILE,
            ES_EVENT_TYPE_AUTH_CLONE,
            ES_EVENT_TYPE_AUTH_MOUNT,
            ES_EVENT_TYPE_NOTIFY_EXIT,
        ]
        guard es_subscribe(c, &events, UInt32(events.count)) == ES_RETURN_SUCCESS
        else { throw Err.subscribe }
    }

    func stop() {
        if let c = client {
            es_unsubscribe_all(c)
            es_delete_client(c)          // tears down; pending AUTH auto-allow
        }
    }
}
The ordering detail nobody gets right

Mute your own audit token before es_subscribe, not after. Between subscribe and mute there is a window where your own file I/O generates AUTH events that arrive on the queue you're currently blocking. That's a startup deadlock that only reproduces on a busy machine, which is to say: only at a customer. Saying this in an interview is worth more than reciting the whole event list.

§4

Anatomy of es_message_t

Every field here answers an interview question.

struct es_message_t {
    version:        UInt32          // GROWS EVERY macOS RELEASE. Guard on it.
    time:           timespec        // wall clock — for audit records
    mach_time:      UInt64          // monotonic — for latency math
    deadline:       UInt64          // mach_absolute_time units. Respond BEFORE this.
    process:        UnsafeMutablePointer<es_process_t>   // the ACTOR
    seq_num:        UInt64          // per-event-type sequence — gap = you dropped
    action_type:    es_action_type_t // ES_ACTION_TYPE_AUTH | ES_ACTION_TYPE_NOTIFY
    action:         union { auth, notify }
    event_type:     es_event_type_t
    event:          union { open, exec, close, rename, ... }   // TAGGED BY event_type
    thread:         UnsafeMutablePointer<es_thread_t>?   // version 4+
    global_seq_num: UInt64          // across all types — the real drop detector
}
FieldWhy it matters
versionThe struct is versioned, and newer macOS adds fields to the end of sub-structs. If you read a v6 field on a v4 message you read garbage. Real clients do if msg.pointee.version >= 4 { ... }. This is the #1 source of "works on my Sonoma, crashes on their Ventura."
deadlineNot a constant. Varies by event type and system state. Always compute your budget from it, never from a hardcoded ms value. §7.
global_seq_numMonotonic across all events. A gap means the kernel dropped messages because you were too slow — this is your drop metric, and a security product that silently drops events is lying to its customer. Export it.
processThe actor. Never the target. For AUTH_EXEC the new program is in event.exec.target, and msg.process is the parent doing the exec. Mixing these two up is the classic bug.
action_typeBranch on it before responding. Calling es_respond_auth_result on a NOTIFY message is an error; forgetting to respond to an AUTH is fatal.

ppid, original_ppid:    pid_t             // original_ppid survives reparenting to launchd
group_id, session_id:   pid_t
codesigning_flags:      UInt32            // CS_VALID, CS_PLATFORM_BINARY, CS_HARD, CS_KILL…

Gold responsible_audit_token is the field that separates people who read the docs from people who shipped. When Terminal launches node, or when an XPC service does work on behalf of an app, the responsible process is the one a human would blame. For AI governance this is decisive: an MCP server spawned by Claude Code has responsible = the IDE, not launchd. That's how you attribute an agent's file reads to the human who started the agent.

§6

Responding to AUTH — and the flags trick

// Most AUTH events: binary verdict
es_respond_auth_result(client, msg, ES_AUTH_RESULT_ALLOW, true)
es_respond_auth_result(client, msg, ES_AUTH_RESULT_DENY,  false)
//                                                          ▲ cache

// AUTH_OPEN ONLY: return the SUBSET of flags you permit
es_respond_flags_result(client, msg, allowedFlags, false)

The flags result, properly understood

es_event_open_t.fflag carries the requested access as fcntl-style flags (FREAD, FWRITE, …), not the O_* constants you'd pass to open(2). You return a mask of what you're willing to permit:

let requested = msg.pointee.event.open.fflag

switch verdict {
case .allow:
    es_respond_flags_result(client, msg, UInt32(bitPattern: requested), true)

case .readOnly:
    // Let it read. Strip write. The app gets an fd, it just can't
    // mutate. Far lower blast radius than a hard failure.
    let allowed = requested & ~(FWRITE | O_APPEND)
    es_respond_flags_result(client, msg, UInt32(bitPattern: allowed), false)

case .deny:
    es_respond_flags_result(client, msg, 0, false)   // open() fails
}
Why this is the most important primitive in DLP

A hard DENY on open() makes applications crash in ways their developers never tested — a text editor that gets EPERM on a file it can see in a Finder dialog will do something stupid. Stripping FWRITE instead means the app opens the file, reads it fine, and fails on save with an error it does know how to handle. That's the difference between a DLP that customers keep and one they uninstall.

Say it like this: "The flags result is why I'd model policy as 'what access do you get' rather than 'yes/no'. Yes/no is a kernel-level API that produces application-level chaos."

The cache argument — a footgun and a superpower

  • cache: true tells the kernel to remember your verdict and stop delivering that event for that target. For AUTH_EXEC on a trusted binary this is enormous: you evaluate /usr/bin/git once instead of ten thousand times during a build.
  • The cost: you stop seeing it. Cached ALLOW means no visibility, which for a telemetry-selling product may be unacceptable. It's a per-event-type product decision, not a perf knob.
  • Never cache a DENY that depends on mutable state (policy version, file label, time of day). You'll cache a decision made under an old policy and be unable to explain it.
  • es_clear_cache(client) flushes. It's global — you flush everyone's cache, including other vendors' clients. Call it on policy update, and know that it's rate-limited by the kernel (ES_CLEAR_CACHE_RESULT_ERR_THROTTLE), so a policy that updates every 30 seconds is a design mistake.
§7

Deadlines, async, and the watchdog

The whole discipline of ES engineering in one section.

Reading the deadline correctly

import Darwin

enum MachClock {
    static let timebase: mach_timebase_info_data_t = {
        var t = mach_timebase_info_data_t()
        mach_timebase_info(&t)
        return t
    }()

    static func nanos(_ machTicks: UInt64) -> UInt64 {
        machTicks &* UInt64(timebase.numer) / UInt64(timebase.denom)
    }

    // How long do I have, right now, for this message?
    static func budget(_ msg: UnsafePointer<es_message_t>) -> TimeInterval {
        let now = mach_absolute_time()
        let dl  = msg.pointee.deadline
        guard dl > now else { return 0 }
        return Double(nanos(dl - now)) / 1_000_000_000
    }
}

Do not hardcode a millisecond value. Apple has changed deadlines between releases and they differ per event type. Every real client computes the remaining budget from the message. Saying this in a room full of people who've been burned by it is a strong move.

The async pattern, with the retain that everyone forgets

private func handle(client: OpaquePointer, msg: UnsafePointer<es_message_t>) {
    guard msg.pointee.action_type == ES_ACTION_TYPE_AUTH else {
        handleNotify(msg)      // no response needed; still copy anything you keep
        return
    }

    // FAST PATH: cache hit → respond inline, no hop, no allocation.
    if let verdict = policyCache.lookupFast(msg) {
        respond(client, msg, verdict)
        return
    }

    // SLOW PATH: we must leave this callback. Retain or the memory dies.
    es_retain_message(msg)

    let budget = MachClock.budget(msg)
    let responded = Atomic<Bool>(false)

    // WATCHDOG: we choose our own timeout at a FRACTION of the deadline,
    // so the kernel never has to choose for us.
    workQueue.asyncAfter(deadline: .now() + budget * 0.5) {
        if responded.compareExchange(expected: false, desired: true) {
            self.metrics.watchdogFired += 1
            self.respond(client, msg, .failOpen)   // ALLOW. Always allow on timeout.
            es_release_message(msg)
        }
    }

    workQueue.async {
        let v = self.policy.evaluate(msg)          // may touch the label store
        if responded.compareExchange(expected: false, desired: true) {
            self.respond(client, msg, v)
            es_release_message(msg)
        }
    }
}

The rule Nothing on the callback queue may block. No mutex another queue can hold. No XPC round trip. No read(). No network. No regex over file content. No NSLog. The callback queue does one thing: look up a precomputed answer, or hand off and get out.

What "fail open" means and why it's not cowardice

When the watchdog fires you ALLOW. This feels wrong to security people, so have the argument ready:

  • If you DENY on timeout, an overloaded agent turns into a machine that randomly refuses file access. Every app breaks at once. On a 10,000-Mac fleet you've just caused a company-wide outage from a perf regression.
  • If you don't respond at all, the kernel kills your client — you lose all enforcement anyway, plus you're now in a restart loop re-flooding yourself.
  • So: allow, count it, export the metric, and if the rate crosses a threshold, self-demote to notify-only and alert the backend. You degrade to monitoring instead of dying or breaking the machine.
  • Strict mode (fail-closed) exists as an opt-in for the handful of customers who genuinely prefer an outage to a leak. That's a customer decision, not yours.
"Fail-open isn't a security compromise, it's the recognition that on an endpoint your availability failure is a bigger business risk than the leak you're preventing — and that a dead client enforces nothing anyway. What makes it defensible is the telemetry: every fail-open is counted and reported, so the customer knows exactly what wasn't covered."
§8

Muting — how you survive a real machine

Muting is not an optimisation. On a machine running Xcode it is the difference between a working agent and a brick.

APIWhat it does
es_mute_process(client, &token)Silence an actor by audit token. Your own agent, your helpers, your scanner. Do this first.
es_mute_process_events(client, &token, events, n)Silence an actor for specific events only. Mute your scanner's opens without going blind to its execs.
es_mute_path(client, path, type)ES_MUTE_PATH_TYPE_LITERAL / _PREFIX — mute by actor's executable path. _TARGET_LITERAL / _TARGET_PREFIX — mute by the file being touched. Both matter and people confuse them constantly.
es_mute_path_events(client, path, type, events, n)Path muting scoped to event types.
es_invert_muting(client, type)Flips the semantics: the mute set becomes the only set you watch. Types: ES_MUTE_INVERSION_TYPE_PROCESS, _PATH, _TARGET_PATH.
es_muted_processes_events() / es_muted_paths_events()Read back what you've muted. Essential for diagnostics — "why am I not seeing events" is answered here 90% of the time.

Inverted muting is the DLP superpower

Normal muting is a denylist: watch everything, silence the noise. That's an infinite game — every new tool a developer installs is new noise. Inverted target-path muting flips it: name the 200 sensitive directories you care about, invert, and the kernel delivers only those. Your event rate drops by three orders of magnitude and your deadline problem largely evaporates.

// Watch ONLY these targets. Everything else never reaches userspace.
es_invert_muting(client, ES_MUTE_INVERSION_TYPE_TARGET_PATH)
es_mute_path(client, "/Users/*/Documents/Finance", ES_MUTE_PATH_TYPE_TARGET_PREFIX)
es_mute_path(client, "/Users/*/Downloads",          ES_MUTE_PATH_TYPE_TARGET_PREFIX)

The trade to state out loud: inverted muting is precise and cheap, but it means your coverage is exactly as good as your path list. A user who saves the customer list to ~/Desktop/tmp is invisible. So real products run a hybrid: inverted muting for the AUTH/enforcement path (narrow, fast, blocking), and a broader denylist-muted NOTIFY subscription for discovery and lineage. Two subscription strategies for two jobs. That's a Staff-level answer.

The mute list every macOS agent ends up with
  • Self + helpers + scanner subprocesses (audit token).
  • ~/Library/Caches, ~/Library/Developer/Xcode/DerivedData, /private/var/folders, node_modules, Spotlight's /.Spotlight-V100, Time Machine.
  • Platform binaries you'd never police — but be careful: cp, mv, rsync, curl and osascript are all platform binaries and all are exfil tools. "is_platform_binary → mute" is a bug, not a rule. That distinction is a great thing to volunteer.
  • Other ES clients (is_es_client) — never block another security agent; you'll deadlock the machine between two vendors, and it's happened in the wild.
§9

Swift ↔ C interop — where the real bugs live

ES is a C API with manual memory management, consumed from a language with ARC. That seam is where the crashes are.

1. Strings are not strings
// es_string_token_t { length: size_t, data: UnsafePointer<CChar>! }
// NOT null-terminated-safe to assume, and NOT valid after the callback.
extension es_string_token_t {
    var string: String {
        guard length > 0, let data else { return "" }
        return String(bytes: UnsafeRawBufferPointer(start: data, count: length),
                      encoding: .utf8) ?? ""
    }
}
// This COPIES. That's the point — the token's memory dies with the message.
2. cdhash is a 20-byte C tuple, which Swift imports as an actual tuple
extension es_process_t {
    var cdHashHex: String {
        var h = cdhash   // (UInt8, UInt8, … × 20) — yes, really
        return withUnsafeBytes(of: &h) { buf in
            buf.map { String(format: "%02x", $0) }.joined()
        }
    }
}
3. argv requires the accessor functions, not pointer arithmetic
func argv(_ exec: inout es_event_exec_t) -> [String] {
    let n = es_exec_arg_count(&exec)
    return (0..<n).map { es_exec_arg(&exec, $0).string }
}
// Same shape for es_exec_env_count/es_exec_env — env is where API keys live,
// which is exactly why MCP server configs are interesting (§25) and also why
// you must NEVER log env verbatim into your audit pipeline.
4. Ownership at the boundary — wrap it
// The bug: capturing msg in an escaping closure without retaining.
// Reproduces only under load. Costs you a week.
final class RetainedMessage {
    let ptr: UnsafePointer<es_message_t>
    init(_ p: UnsafePointer<es_message_t>) { ptr = p; es_retain_message(p) }
    deinit { es_release_message(ptr) }
}
// Now ARC owns the lifetime and the failure mode is impossible by construction.
5. Version guards, everywhere
if msg.pointee.version >= 4 {
    let responsible = msg.pointee.process.pointee.responsible_audit_token
    ...
}
// Compile against the newest SDK; guard at runtime on version, not on
// #available alone — the struct version is a per-MESSAGE fact.
"The genre of bug I'd warn a new hire about isn't the ES logic, it's the seam. es_message_t is C memory with a manual retain, and Swift closures make it trivially easy to capture something that's already been freed. I'd wrap the message in a small RAII type at the boundary on day one so nobody in the codebase ever touches es_retain_message by hand."
§10

Process identity — the question people fail

Wrong pid, process name, executable path. All three are attacker-controlled or racy. pid reuse: the process exits between your check and your action, the pid is recycled, you authorise the wrong program. Path: copy any binary to /tmp/Chrome. Name: argv[0] is a lie by design.

Right cdhash = this exact binary. team_id + signing_id = any build from this vendor with this identifier. codesigning_flags & CS_VALID = the signature is intact right now. audit_token = the process instance, unforgeable, no reuse race.

Policy identity, in order of strictness

struct Actor: Hashable {
    let cdHash: String        // pin exact build (brittle: breaks every update)
    let teamID: String        // pin vendor (right default for "allow Chrome")
    let signingID: String     // pin identifier within vendor
    let isPlatform: Bool
    let csValid: Bool
}

func actor(from p: UnsafePointer<es_process_t>) -> Actor {
    Actor(cdHash: p.pointee.cdHashHex,
          teamID: p.pointee.team_id.string,
          signingID: p.pointee.signing_id.string,
          isPlatform: p.pointee.is_platform_binary,
          csValid: p.pointee.codesigning_flags & UInt32(CS_VALID) != 0)
}

The unsolved case — and you must name it

Every AI agent runtime defeats binary identity. node is node. python3 is python3. Every MCP server on the machine has the identical cdhash, team ID, and signing ID, because they're all the same interpreter. Code-signature identity — the entire foundation of macOS app policy — collapses the moment the thing you want to police is a script.

So you fall back to a composite identity:

  • interpreter cdhash (weak, but tells you it's really node and not a renamed binary)
  • + argv (the script path, the package name, the args) — from AUTH_EXEC
  • + the script file's own hash — you have es_event_exec_t.script for shebang'd scripts, and for node foo.js you resolve argv[1] and hash it
  • + the responsible process (v4 responsible_audit_token) — Claude Code vs Terminal vs cron is a huge signal
  • + the process subtree — you maintain the tree from FORK/EXEC/EXIT and inherit policy down it
"Identity for scripts is genuinely unsolved on macOS, and I'd rather say that than pretend. The composite I'd use is interpreter + argv + script hash + responsible process + subtree inheritance. It's weaker than a cdhash and an attacker who controls argv can play games with it — so I'd treat it as a governance control for well-meaning users, not a security boundary against a determined insider. Those are different products and conflating them is how DLP gets a bad name."

The label cache — how classification and enforcement coexist

This is the central architectural idea of endpoint DLP. If you only take one design away, take this.

The impossibility

You cannot classify a file inside an AUTH deadline. Reading the file requires I/O (which you can't do on the callback queue), and scanning it requires CPU you don't have. Yet enforcement must happen at AUTH time, because that's the only moment you can stop anything. Resolution: decouple in time. Classify asynchronously, cache the label, and make the AUTH path a hash lookup.

      [ classify queue ]                    [ ES callback queue ]

struct FileKey: Hashable {
    let dev: dev_t          // which volume — this is also your USB check
    let ino: ino_t
    let gen: UInt32         // APFS generation — defeats inode reuse
    let size: off_t         // cheap change detector
    let mtime: timespec

    init(_ f: UnsafePointer<es_file_t>) {
        let st = f.pointee.stat
        dev = st.st_dev; ino = st.st_ino; gen = st.st_gen
        size = st.st_size; mtime = st.st_mtimespec
    }
}

final class LabelCache {
    private var map: [FileKey: Label] = [:]        // bounded LRU in reality
    private var epoch: UInt64 = 0                  // policy version
    private let lock = os_unfair_lock_s()          // NOT a DispatchQueue —
                                                   // you cannot afford a hop here
    func lookup(_ k: FileKey) -> Label? { ... }

    // Policy changed? Don't walk the map. Bump the epoch;
    // every entry is now stale by construction. O(1) invalidation.
    func invalidateAll() { epoch &+= 1 }
}

The three questions an interviewer will ask about this

  1. "What if the label is missing at AUTH time?" — Cold-start reality. Options: (a) fail-open + log + queue for classification, (b) block-and-scan with a hard sub-deadline timeout, (c) a coarse pre-filter (path is in a sensitive tree → treat as restricted until proven otherwise). Ship (a) by default with (c) for the highest-severity paths, and let the customer opt into (b). Give all three and pick.
  2. "Inode reuse?" — st_gen where available, plus size+mtime as a composite. On APFS the generation counter is the right answer; be honest that it isn't populated on every filesystem, and that's why you carry the composite.
  3. "Memory?" — Bounded LRU with a hard cap and an eviction metric. A build machine touches millions of files; an unbounded cache is an OOM in an extension that must never die. Evictions cause cache misses cause fail-opens — so eviction rate is a security metric, not a perf metric. That framing is the one that lands.

import EndpointSecurity

final class DLPSensor {

    // ── State ────────────────────────────────────────────────
    private var client: OpaquePointer?
    private let esQueue    = DispatchQueue(label: "es.callback", qos: .userInteractive)
    private let workQueue  = DispatchQueue(label: "es.work",
                                          qos: .userInitiated, attributes: .concurrent)
    private let scanQueue  = DispatchQueue(label: "es.scan", qos: .utility)
    private let labels     = LabelCache()
    private var policy     = PolicySnapshot.empty   // immutable; swapped atomically
    private let log = OSLog(subsystem: "ai.nf.sensor", category: "es")
    private let metrics = Metrics()
    private var mode: Mode = .enforce             // .enforce | .monitor  (self-demote)

    // ── Lifecycle ────────────────────────────────────────────
    func start() throws {
        var c: OpaquePointer?
        let r = es_new_client(&c) { [unowned self] cl, m in self.dispatch(cl, m) }
        guard r == ES_NEW_CLIENT_RESULT_SUCCESS, let c else { throw Err(r) }
        client = c

        // 1 — self-mute BEFORE subscribe (§3)
        if var me = selfAuditToken() { es_mute_process(c, &me) }

        // 2 — kill the noise before it reaches us
        for p in ["/private/var/folders", "/System/Volumes/Data/.Spotlight-V100"] {
            es_mute_path(c, p, ES_MUTE_PATH_TYPE_TARGET_PREFIX)
        }

        // 3 — subscribe
        var ev: [es_event_type_t] = [
            ES_EVENT_TYPE_AUTH_OPEN,       ES_EVENT_TYPE_AUTH_COPYFILE,
            ES_EVENT_TYPE_AUTH_CLONE,      ES_EVENT_TYPE_AUTH_RENAME,
            ES_EVENT_TYPE_AUTH_EXEC,       ES_EVENT_TYPE_AUTH_MOUNT,
            ES_EVENT_TYPE_NOTIFY_CLOSE,    ES_EVENT_TYPE_NOTIFY_FORK,
            ES_EVENT_TYPE_NOTIFY_EXIT,
        ]
        guard es_subscribe(c, &ev, UInt32(ev.count)) == ES_RETURN_SUCCESS
        else { throw Err.subscribe }
        os_log("sensor up, %d events", log: log, type: .info, ev.count)
    }

    // ── Dispatch ─────────────────────────────────────────────
    private func dispatch(_ c: OpaquePointer, _ m: UnsafePointer<es_message_t>) {
        metrics.observe(seq: m.pointee.global_seq_num)   // gap ⇒ we dropped

        if m.pointee.action_type == ES_ACTION_TYPE_NOTIFY {
            switch m.pointee.event_type {
            case ES_EVENT_TYPE_NOTIFY_CLOSE:
                let e = m.pointee.event.close
                if e.modified {
                    let key = FileKey(e.target)
                    let path = e.target.pointee.path.string     // COPY now
                    scanQueue.async { self.classify(path, key) }  // off-path
                }
            case ES_EVENT_TYPE_NOTIFY_FORK: tree.onFork(m)
            case ES_EVENT_TYPE_NOTIFY_EXIT: tree.onExit(m)
            default: break
            }
            return
        }

        // ── AUTH from here. A thread is blocked. Move. ──
        guard mode == .enforce else { allow(c, m); return }

        switch m.pointee.event_type {
        case ES_EVENT_TYPE_AUTH_OPEN:     authOpen(c, m)
        case ES_EVENT_TYPE_AUTH_EXEC:     authExec(c, m)
        case ES_EVENT_TYPE_AUTH_COPYFILE,
             ES_EVENT_TYPE_AUTH_CLONE,
             ES_EVENT_TYPE_AUTH_RENAME:   authMove(c, m)
        case ES_EVENT_TYPE_AUTH_MOUNT:    authMount(c, m)
        default:                          allow(c, m)
        }
    }

    // ── AUTH_OPEN: the hot path ──────────────────────────────
    private func authOpen(_ c: OpaquePointer, _ m: UnsafePointer<es_message_t>) {
        let ev = m.pointee.event.open
        let requested = ev.fflag

        // Reads are never a DLP violation on their own — allow + cache.
        guard requested & FWRITE != 0 else {
            es_respond_flags_result(c, m, UInt32(bitPattern: requested), true)
            return
        }

        let key = FileKey(ev.file)
        let actor = actor(from: m.pointee.process)

        // O(1). No I/O. No allocation we can avoid. No lock anyone else holds.
        let verdict = policy.evaluate(actor: actor,
                                      target: key,
                                      label: labels.lookup(key),
                                      volume: volumes.classify(key.dev))

        switch verdict {
        case .allow:
            es_respond_flags_result(c, m, UInt32(bitPattern: requested), true)
        case .readOnly:
            es_respond_flags_result(c, m, UInt32(bitPattern: requested & ~FWRITE), false)
        case .deny:
            es_respond_flags_result(c, m, 0, false)
            audit(m, .blocked)                       // async, AFTER responding
        case .unknown:
            // no label yet → fail open, classify, count it
            es_respond_flags_result(c, m, UInt32(bitPattern: requested), false)
            metrics.unlabelledAllow += 1
            let path = ev.file.pointee.path.string
            scanQueue.async { self.classify(path, key) }
        }
    }

    // ── AUTH_EXEC: where AI governance starts (Part III) ─────
    private func authExec(_ c: OpaquePointer, _ m: UnsafePointer<es_message_t>) {
        var ev = m.pointee.event.exec
        let target = ev.target.pointee
        let args   = argv(&ev)
        let parent = m.pointee.process.pointee
        let responsible = m.pointee.version >= 4
            ? m.pointee.process.pointee.responsible_audit_token : nil

        if let mcp = MCPClassifier.identify(exe: target.executable.pointee.path.string,
                                           argv: args,
                                           parent: parent,
                                           responsible: responsible) {
            workQueue.async { self.recordMCPLaunch(mcp) }        // inventory
            if policy.blocks(mcp) {
                es_respond_auth_result(c, m, ES_AUTH_RESULT_DENY, false)
                return
            }
        }
        es_respond_auth_result(c, m, ES_AUTH_RESULT_ALLOW, true)   // cache: exec is hot
    }

    private func allow(_ c: OpaquePointer, _ m: UnsafePointer<es_message_t>) {
        if m.pointee.event_type == ES_EVENT_TYPE_AUTH_OPEN {
            es_respond_flags_result(c, m, UInt32(bitPattern: m.pointee.event.open.fflag), false)
        } else {
            es_respond_auth_result(c, m, ES_AUTH_RESULT_ALLOW, false)
        }
    }
}

Read the shape, not the syntax Notice what's not in the hot path: no I/O, no string formatting, no logging, no XPC, no allocation of anything unbounded. The whole design exists to make authOpen a hash lookup and a syscall. Every other decision in the file is downstream of that constraint. If you can articulate that in the interview, the specific API names barely matter.

The content filter, in code

The two-provider split

A content filter is two extensions working together, and this design confuses everyone the first time:

  • Data provider — in the fast path. Sees every flow. Memory-constrained, must be quick, cannot do network I/O of its own.
  • Control provider — the slow path. When the data provider returns .needRules(), the flow is parked and the control provider is asked; it can do expensive things (ask your backend, ask your daemon over XPC) and then supplies a rule.

That's the same decoupling as §11: fast path looks up, slow path decides. Point out the symmetry with the ES deadline design and you sound like someone with a coherent model of the platform rather than two memorised APIs.

import NetworkExtension

final class FilterDataProvider: NEFilterDataProvider {

    override func startFilter(completionHandler: @escaping (Error?) -> Void) {
        // Pre-filter in the kernel so most flows never reach us at all.
        let rules = AIEndpoints.all.map { host in
            NEFilterRule(networkRule: NENetworkRule(remoteNetwork: nil,
                                                    remotePrefix: 0,
                                                    localNetwork: nil,
                                                    localPrefix: 0,
                                                    protocol: .TCP,
                                                    direction: .outbound),
                         action: .filterData)
        }
        let settings = NEFilterSettings(rules: rules, defaultAction: .allow)
        apply(settings) { _ in completionHandler(nil) }
    }

    override func handleNewFlow(_ flow: NEFilterFlow) -> NEFilterNewFlowVerdict {
        guard let socket = flow as? NEFilterSocketFlow else { return .allow() }

        // WHO — see §17. This is the whole value of the filter over a proxy.
        let appID = flow.sourceAppIdentifier ?? "<unknown>"
        let host  = socket.remoteHostname
                 ?? (socket.remoteEndpoint as? NWHostEndpoint)?.hostname
                 ?? ""

        switch policy.classify(app: appID, host: host) {
        case .allowSilently:
            return .allow()

        case .blockUnsanctionedAI:
            report(.blocked(app: appID, host: host))
            return .drop()

        case .observeAI:
            // Peek at the head of the stream. We get ciphertext for TLS,
            // but we get the ClientHello — and SNI is in there in the clear
            // unless ECH is in play.
            return .filterDataVerdict(withFilterInbound: false, peekInboundBytes: 0,
                                       filterOutbound: true,  peekOutboundBytes: 2048)

        case .needsBackendDecision:
            // Park it. The control provider gets asked. Costs latency —
            // use sparingly or you make the network feel broken.
            return .needRules()
        }
    }

    override func handleOutboundData(from flow: NEFilterFlow,
                                     readBytesStartOffset offset: Int,
                                     readBytes bytes: Data) -> NEFilterDataVerdict {
        // TLS ⇒ this is ciphertext. The ONLY useful thing here is the
        // ClientHello SNI at offset 0. Say this — it's the honest limit.
        if offset == 0, let sni = TLS.parseSNI(bytes) {
            report(.aiEndpointContacted(app: flow.sourceAppIdentifier, sni: sni))
            if policy.blocksHost(sni) { return .drop() }
        }
        return .allow()      // stop inspecting; let it run at full speed
    }
}

Flow attribution — the "who" that makes it DLP

A network appliance sees an IP. Your extension sees a process. That difference is the entire reason the endpoint agent exists.

override func handleNewFlow(_ flow: NEFilterFlow) -> NEFilterNewFlowVerdict {

    // The easy one — a signing-identifier-ish string. Convenient, but it's
    // just a string, and unsigned/renamed binaries make it unreliable alone.
    let appID = flow.sourceAppIdentifier

    // The real one (macOS): the peer's audit token.
    if let tokenData = flow.sourceAppAuditToken, tokenData.count == MemoryLayout<audit_token_t>.size {
        var token = audit_token_t()
        _ = withUnsafeMutableBytes(of: &token) { tokenData.copyBytes(to: $0) }

        // (a) validate the code signature from the token — §18 in Part I terms
        let identity = CodeIdentity.validate(auditToken: token)

        // (b) THE MOVE: this token is the SAME identity ES gave you.
        //     Join the network flow to the process record, the process tree,
        //     and the files that process has been reading. That's lineage.
        let proc = processTree.lookup(auditToken: token)
        let recentSensitiveReads = proc?.recentReads(where: { $0.label == .restricted })

        if let reads = recentSensitiveReads, !reads.isEmpty,
           policy.isUnsanctionedAI(flow) {
            // "This process read the customer list 4 seconds ago and is now
            //  opening a TLS connection to an unsanctioned model endpoint."
            return .drop()
        }
    }
    return .allow()
}
This is the answer to "why do you need both ES and NetworkExtension?"

Not "files and network". Because the audit token is the join key. ES gives you what a process read; NE gives you where that process is sending. The audit token lets you join them into a single causal story — read customer list → connect to unsanctioned AI host — and that story is the product. It's what Nightfall calls data lineage, and it's the thing a network-only vendor and a file-only vendor both structurally cannot do.

Caveats to volunteer: sourceAppAuditToken isn't always populated (kernel-originated traffic, some system daemons, and flows from processes that have already exited by the time you look). Attribution is best-effort and you design for the unattributed tail rather than pretending it doesn't exist.

Transparent proxy — when you need the bytes

final class AIProxyProvider: NETransparentProxyProvider {

    override func startProxy(options: [String: Any]?,
                            completionHandler: @escaping (Error?) -> Void) {
        let settings = NETransparentProxyNetworkSettings(tunnelRemoteAddress: "127.0.0.1")

        // SCOPE IT. Do not proxy the internet. Proxy the AI endpoints and
        // nothing else — everything you include is latency you own and a
        // TLS edge case you inherit.
        settings.includedNetworkRules = AIEndpoints.hosts.map { host in
            NENetworkRule(remoteNetwork: NWHostEndpoint(hostname: host, port: "443"),
                          remotePrefix: 0, localNetwork: nil, localPrefix: 0,
                          protocol: .TCP, direction: .outbound)
        }
        setTunnelNetworkSettings(settings) { completionHandler($0) }
    }

    override func handleNewFlow(_ flow: NEAppProxyFlow) -> Bool {
        guard let tcp = flow as? NEAppProxyTCPFlow else { return false }  // false = don't handle
        let remote = tcp.remoteEndpoint as? NWHostEndpoint

        tcp.open(withLocalEndpoint: nil) { err in
            guard err == nil else { return }
            // Now: terminate TLS locally with a cert we mint from the corporate
            // CA, read the plaintext, classify it, and re-originate upstream
            // with a real TLS session of our own.
            self.pump(tcp, to: remote)
        }
        return true
    }

    private func pump(_ flow: NEAppProxyTCPFlow, to remote: NWHostEndpoint?) {
        flow.readData { data, err in
            guard let data, !data.isEmpty, err == nil else { flow.closeReadWithError(err); return }

            // data here is PLAINTEXT after our TLS termination.
            // This is where prompt DLP actually happens.
            if let body = HTTP.body(data), let finding = self.classifier.scan(body) {
                if self.policy.blocks(finding) {
                    flow.write(HTTP.forbidden(reason: finding)) { _ in flow.closeWriteWithError(nil) }
                    self.report(finding)
                    return
                }
            }
            self.upstream.send(data)
            self.pump(flow, to: remote)      // keep reading
        }
    }
}

Say the costs out loud A transparent proxy means you own: TLS versions, ALPN and HTTP/2 (and QUIC, which you'll probably have to block outright to force TCP fallback — that's a real technique, name it), certificate pinning (which breaks hard and silently for apps that pin), Apple's own services bypassing you, and every connection on the machine's latency. You will be blamed for every network problem the customer has for the next year. It's the right tool for a small, named set of high-value hosts and the wrong tool for everything.

§19

TLS interception, honestly

  1. The CA. Generate a corporate root, push it to the System keychain as trusted via an MDM certificate payload. Without MDM this is a non-starter — another reason the deployment story is the product story.
  2. Mint on the fly. On each intercepted flow, generate a leaf for the SNI hostname, signed by your CA, and present it. Cache the leaves; key generation is expensive.
  3. Re-originate upstream with a real TLS session and validate the real chain properly. If you don't, you've downgraded every user's security to your bug count.
  4. Pinning defeats you. Apps that pin — many native clients, some SDKs — will simply fail. Your only options are: exclude them from the proxy (and lose visibility), or break them (and lose the customer). There is no third option. State this plainly; it's the mark of someone who's done it.
  5. Certificate Transparency & ECH. Encrypted Client Hello removes SNI from the clear, which erodes even the cheap filter-level visibility over time. Worth naming as the trend that makes endpoint-side interception more necessary, not less — a nice forward-looking point in an interview.
"My honest position on MITM: it's a capability you build for a specific, small allowlist of destinations where the content genuinely matters — the AI endpoints, the file-sharing hosts — and never as a default posture. Every host you add is a support burden forever. The honest limitation, which you volunteer before being asked: DoH and DoT bypass this completely. Chrome and Firefox default to encrypted DNS; so does a growing share of native software. So a DNS proxy is a good, cheap discovery signal for the long tail of naive clients, and worthless as a control. Build it in an afternoon, treat its coverage as partial, never sell it as enforcement.

§21

Limits & failure modes

  • Memory. A filter data provider is a long-lived, memory-constrained process — on iOS the content filter budget is famously tiny, and while macOS is more generous, the design assumption is identical: never buffer a flow. Peek a bounded prefix, decide, get out. A provider that OOMs takes the customer's network with it.
  • Fail-open, again. If your provider crashes, what happens to the network? Test it. The answer should be "traffic flows"; if the answer is "the Mac loses the internet", you have a company-ending bug in an auto-updating product.
  • Ordering. Multiple filters can be installed. You are not the only one. Same lesson as ES.
  • Apple bypasses. Some Apple traffic is exempt from filtering by design. Your coverage claim must account for it rather than pretend.
  • The extension can be killed and restarted under memory pressure; hold no state you can't rebuild, and never hold state in the provider that policy depends on — that belongs in the daemon, reachable over XPC.
  • Debugging: log stream --predicate 'subsystem BEGINSWITH "com.apple.networkextension"', plus your own subsystem; nettop, tcpdump on utun interfaces for proxies, and Console for provider start failures — which are usually entitlement or profile problems, not code problems.

Three implementation notes that show you've thought past the diagram:

§24

AI application inventory

Before you govern anything you have to know what's on the machine. This is the v1 that ships in a month.

  1. Installed: enumerate /Applications + user apps, match bundle IDs and team IDs against a curated catalogue of AI apps. Cheap, static, incomplete.
  2. Executed: ES NOTIFY_EXEC — you see everything that actually runs, including the CLI tools an installed-apps scan will never find. Match on cdhash/team, and on argv for interpreted tools.
  3. Resolved: DNS proxy — who looked up which provider. Partial (DoH), free.
  4. Connected: NE filter, SNI + app attribution. The most reliable signal for native apps.
  5. Configured: watch the config files — ~/.claude.json, claude_desktop_config.json, .cursor/, .mcp.json, shell rc files exporting ANTHROPIC_API_KEY/OPENAI_API_KEY. This finds intent before behaviour.

The insight to voice: these five sources disagree, and the disagreements are the interesting findings. An app that's installed but never runs is noise. A binary that runs and connects but isn't in your catalogue is shadow AI — the actual thing the customer is buying. Design the inventory as a reconciliation across sources, not as a list.

§28

Question bank

Why can't you just scan the file inside the AUTH callback?

Because a thread is blocked in the kernel and the deadline is not yours to choose. File I/O on the callback queue is unbounded latency, it needs TCC, and reading the file generates the very AUTH_OPEN you're currently handling unless you've muted yourself — that's a self-deadlock. So classification is decoupled in time: label on NOTIFY_CLOSE(modified), cache by (dev, inode, generation), and make the AUTH path an O(1) lookup with a watchdog that fails open at half the deadline.

Difference between es_respond_auth_result and es_respond_flags_result?

Flags result is AUTH_OPEN-only and lets you return the subset of fcntl flags you permit — so you can allow read and strip write on the same open. That matters because a hard DENY makes apps fail in untested code paths, whereas a read-only fd makes them fail at save with an error they know how to show. Everything else is the binary auth result. Both take a cache flag; caching an ALLOW makes you blind to that target, caching a DENY freezes a decision made under a policy version that may change.

Walk me through detecting an MCP server launch.

AUTH_EXEC. Check whether msg.process — or better, responsible_audit_token at message version ≥ 4 — is an AI runtime by signing ID. Pull argv with es_exec_arg_count/es_exec_arg; match on modelcontextprotocol, mcp-server, uvx, or a known-package list. Extract the capability from argv — the filesystem root it's given, the DB it's pointed at — because the risk is the scope, not the name. Count secrets in env but never log their values. Cross-reference against the declared config in claude_desktop_config.json / .mcp.json: a server that runs but isn't declared is your highest-signal finding. And be upfront that the stdio traffic itself is unreadable — this is inventory and capability, not content interception.

How do you attribute a network flow to a process?

NEFilterFlow.sourceAppAuditToken, then validate the code signature from that token — never trust sourceAppIdentifier alone, it's a string. The real payoff is that the audit token is the same key ES gives you, so you join the flow to the process record, its tree, and its recent file reads. That join is what produces lineage: "read the customer list four seconds ago, now opening TLS to an unsanctioned model endpoint." A network vendor can't do it and a file-only vendor can't do it. Caveat: the token isn't always populated, so you design for an unattributed tail.

Your extension needs a backend decision on a flow. What do you do?

Ideally nothing — the fast path should have a cached answer. If I genuinely must, .needRules() parks the flow and asks the control provider, which can do the expensive thing; or .pause() and resume from a local async lookup. Both are user-visible hangs if slow, so they're a last resort with a hard timeout and a fail-open default. It's structurally the same problem as the ES deadline: fast path looks up, slow path decides, and the timeout is yours to choose so the system never chooses for you.

Why not just MITM everything?

Because you inherit every TLS edge case on the platform and you get blamed for every network problem the customer has. Pinned apps break with no workaround. QUIC forces you to block UDP/443 to fall back to TCP. Apple's own traffic bypasses you anyway. And for the sanctioned providers you don't need it — the provider's compliance API gives you the same content with none of the fight. So: MITM a small named host list where the content genuinely matters, filter for everything else, and use the provider API for the sanctioned centre.

ES or NetworkExtension — which would you build first for AI governance?

ES, and not because it's my comfort zone. Inventory precedes control, and AUTH_EXEC plus config watching gives you the complete picture of what AI tooling exists on the fleet — including the CLI and MCP surface that no network sensor can see at all — in weeks, monitor-only, with near-zero risk of breaking anything. That's a shippable product on its own and it's what earns you the right to enforce later. The network side is where enforcement and prompt content live, and it's a much bigger blast radius, so it comes second and scoped narrowly.

What's the hardest bug you'd expect in this codebase?

The Swift/C seam under load: an es_message_t captured in an escaping closure without es_retain_message, use-after-free that only fires when the work queue is deep enough to outlive the callback. Second: struct-version bugs that only show up on the one macOS version you didn't test. Third — and worst because it isn't a crash — a mute that's slightly too broad, so you silently stop seeing a class of event and your coverage claim becomes false with nothing in the logs. That last one is why I'd want es_muted_paths_events() readback exported as telemetry, not just used in debugging.

§30

Traps

Don't Claim ES can see clipboard, network, or pipe contents. It can't, and the person across the table built this at CrowdStrike and FireEye.

Don't Say "we'd just hook it" or reach for injection. SIP and the hardened runtime ended that era, and reaching for it marks you as someone whose macOS knowledge stopped in 2018.

Don't Mute all platform binaries. cp, curl, rsync, osascript, ditto are platform binaries and they're the exfil toolkit. Volunteer this — it's a nice inversion of an obvious-sounding rule.

Don't Hedge. "It depends on the requirements, there are trade-offs" is the register that cost you the Zscaler round. Commit to a design, then name its weakness yourself. Naming your own design's blind spot before the interviewer does is the strongest move available in this format.

Do Say "I haven't shipped that; here's how I'd reason about it" when it's true. Against an interviewer who has shipped it, an honest boundary plus correct reasoning beats a confident claim that collapses on the second follow-up. Every single time.
